# SIS

Subscriber Information System — a small HTTP service that returns and updates
subscriber profile data by MSISDN, backed by PostgreSQL (or an in-memory store
for tests and benchmarks).

## Features

- HTTP API with validation of MSISDN length, digits, CC and NDC.
- PostgreSQL store (pgx + sqlc) with upsert, per-request DB timeout.
- Startup check: the service refuses to start if the database is unreachable
  or the `subscribers` table does not match the expected schema.
- Fast background generation of test data (`COPY` in batches of 100k).
- Liveness (`/`) and readiness (`/ready`) probes.
- Prometheus metrics: request and store latency histograms, connection pool state, Go runtime.
- Graceful shutdown on `SIGINT`/`SIGTERM`.
- Docker Compose for local development.

Requires Go 1.26+.

## API

Base URL depends on `SIS_ADDR` (`:9001` by default, `:8080` in `.env.example`).

### `GET /subscribers/:msisdn`

Returns the subscriber or an error payload.

```json
{
  "msisdn": 380671234567,
  "billing_type": 1,
  "language_type": 0,
  "operator_type": 1,
  "updated_at": "2024-05-09T09:25:16.482581Z"
}
```

### `PUT /subscribers/:msisdn`

Creates or replaces the subscriber profile. All fields are required and must
not be negative. Responds with `200 OK` and an empty body.

```json
{
  "billing_type": 2,
  "language_type": 1,
  "operator_type": 0
}
```

### Errors

```json
{
  "error_id": 1,
  "error_msg": "Not found"
}
```

| `error_id` | HTTP | Meaning |
| --- | --- | --- |
| `1` | 404 | Subscriber not found |
| `2` | 400 | Invalid MSISDN format (length or non-digits) |
| `3` | 400 | Unsupported CC |
| `4` | 400 | Unsupported NDC |
| `5` | 400 | Invalid request body (bad JSON, missing or negative field) |
| `10` | 500 | Database error |
| `11` | 504 | Database timeout (`SIS_DB_TIMEOUT`) |

### `GET /`

Liveness probe, always `200 OK` while the process is serving HTTP.

### `GET /ready`

Readiness probe: `200 OK` if the database answers a ping, `503` otherwise.

### `GET /metrics`

Prometheus metrics (text format):

| Metric | Type | Labels | Meaning |
| --- | --- | --- | --- |
| `sis_requests_total` | counter | `method`, `code` | Subscriber API requests |
| `sis_request_duration_seconds` | histogram | `method`, `code` | Request latency (validation + store call) |
| `sis_store_duration_seconds` | histogram | `op` (`get`/`set`), `result` (`ok`/`not_found`/`timeout`/`error`) | Store call latency; for PostgreSQL includes waiting for a pool connection |
| `sis_db_pool_acquired_conns`, `_idle_conns`, `_total_conns`, `_constructing_conns`, `_max_conns` | gauge | – | pgx pool state |
| `sis_db_pool_acquires_total`, `_acquire_duration_seconds_total` | counter | – | Connection acquires and time spent on them |
| `sis_db_pool_empty_acquires_total`, `_empty_acquire_wait_seconds_total` | counter | – | Acquires that waited because the pool was exhausted |
| `sis_db_pool_canceled_acquires_total`, `_new_conns_total` | counter | – | Acquires cancelled by timeout; connections opened |
| `go_*`, `process_*` | – | – | Go runtime and process metrics |
| `subscribers_total` | counter | – | Deprecated: number of GET requests, use `sis_requests_total` |

Useful queries:

```promql
# p99 latency of successful GETs
histogram_quantile(0.99, sum by (le) (rate(sis_request_duration_seconds_bucket{method="GET",code="200"}[5m])))

# share of request time spent in the store (≈1 means the database is the bottleneck)
sum(rate(sis_store_duration_seconds_sum[5m])) / sum(rate(sis_request_duration_seconds_sum[5m]))

# pool exhaustion: acquires per second that had to wait for a free connection
rate(sis_db_pool_empty_acquires_total[5m])
```

## Configuration

Environment variables are parsed via `github.com/caarlos0/env/v11`.

| Variable | Default | Description |
| --- | --- | --- |
| `SIS_DB_URL` | `postgresql://sis:XXXX@localhost:5432/sis?sslmode=disable` | PostgreSQL DSN |
| `SIS_DB_MAX_CONNS` | `64` | Max connections in the pool |
| `SIS_DB_TIMEOUT` | `2s` | Timeout of a single DB call per request |
| `SIS_ADDR` | `:9001` | HTTP listen address |
| `SIS_CC` | `380` | Country code |
| `SIS_NDCS` | `50,67,68,69,70,71` | Comma-separated list of supported NDCs |
| `SIS_NDC_CAPACITY` | `10000000` | Numbers per NDC generated by `SIS_GENERATE` |
| `SIS_MSISDN_LENGTH` | `12` | Expected MSISDN length |
| `SIS_GENERATE` | `false` | Fill the database with random subscribers in the background on startup |
| `TZ` | – | Time zone (tzdata is embedded in the binary) |

Copy `.env.example` to `.env` for local development; the Makefile and Docker
Compose read it.

## Database

Migrations are managed with Goose in `sql/schema`:

```bash
make migration_up
make migration_down
```

Docker Compose runs `db/conf/init.sql` when it initialises an empty data
directory; keep it aligned with the migrations. An existing `db/data` volume
is not touched — if the service refuses to start with a schema error, migrate
or recreate the database (`make clean` deletes `db/data`).

SQLC config lives in `sqlc.yaml` with schema in `sql/schema` and queries in
`sql/queries`. Generated code goes to `internal/database`:

```bash
make generate_database_code
```

### Test data

With `SIS_GENERATE=true` the service fills `subscribers` with
`len(SIS_NDCS) × SIS_NDC_CAPACITY` random profiles, e.g. `380670000000` …
`380679999999` for NDC 67. Generation runs in the background — the API is
available immediately — and stops on shutdown; already committed batches stay.
Existing rows are overwritten.

## Local Development

### Docker Compose

```bash
cp .env.example .env   # once
make start             # builds the image from the current code and starts db + sis
make restart           # rebuild and restart after code changes
```

Service ports:

- PostgreSQL: `localhost:5443`
- SIS API: `localhost:9001` (container port `8080`)

### Run Locally

```bash
go run ./cmd/sis
curl http://localhost:8080/subscribers/380670000001
```

## Tests, Lint and Benchmarks

```bash
make test    # go test -race
make lint    # golangci-lint v2, see .golangci.yml
make bench
```

CI (GitHub Actions) runs build, vet, tests and lint on every push and pull request.

## Build

```bash
make image   # docker build for the host architecture
```

## Project Layout

- `cmd/sis` — entry point
- `internal/sis` — config, HTTP server, metrics and stores
- `internal/database` — SQLC-generated DB layer
- `sql/schema`, `sql/queries` — migrations and queries
- `db/conf` — database initialisation for Docker Compose
- `docker-compose.yml` — local stack
